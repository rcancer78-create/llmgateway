# LLMGateway

Шлюз на C#/.NET 8 для работы с локально установленными LLM-клиентами через единый интерфейс библиотеки или HTTP API. Включает адаптеры Codex, Cursor, Antigravity, Grok и Claude Code, а также демонстрационный WPF-чат.

*A .NET gateway for locally installed LLM CLIs, with an OpenAI-compatible text API and a Windows desktop sample.*

**Публичная beta.** Поддерживается часть текстового OpenAI API, а возможности зависят от конкретного CLI и его версии. Публикационная проверка ограничена офлайн-тестами с подставными провайдерами; она не подтверждает текущую работу реальных аккаунтов, квот и всех клиентов. Проект независимый, без связи с поставщиками сервисов.

## Возможности

- Один контракт `ILlmGateway` для библиотечного и HTTP-режима.
- Аккаунты и маршрутизация моделей, явный выбор профиля.
- Текстовые ответы и SSE-стриминг, обработка отмены и ошибок.
- Эмуляция tool calling, stop-последовательности и структурированный текстовый ответ.
- Кэш моделей и квот, если клиент предоставляет эти данные.
- Локальное хранилище настроек аккаунтов и демонстрационный чат.

Для реальных запросов нужен отдельно установленный и авторизованный нативный клиент. Вход выполняется средствами самого клиента. Шлюз не предоставляет подписку, API-ключи или дополнительную квоту.

## Сборка и офлайн-тесты

Нужны Windows 10/11, [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) и Node.js 22 в `PATH`. Node используется некоторыми тестами для собственных временных CLI-заглушек; установка LLM-клиентов для тестов не нужна.

Из корня скачанного или клонированного репозитория:

```powershell
dotnet restore LLMGateway.sln
dotnet build LLMGateway.sln -c Release --no-restore -warnaserror
dotnet test tests/LLMGateway.Tests/LLMGateway.Tests.csproj -c Release --no-build --no-restore --nologo --blame-hang --blame-hang-timeout 2m
```

Основной набор тестов использует временные файлы, подставные адаптеры, локальные HTTP-серверы и собственные Node/PowerShell-процессы. Он не вызывает реальные LLM-провайдеры. Полный набор через `dotnet test LLMGateway.sln` дополнительно включает WPF-тесты, которые открывают тестовые окна.

[CI](.github/workflows/ci.yml) выполняет полный набор на Windows с .NET 8 и Node 22, собирает покрытие и после успешных тестов создаёт отдельные переносимые архивы API и ChatApp. Результаты доступны в Actions; наличие workflow не является подтверждением успешного запуска.

## Локальный HTTP API

Перед реальным использованием установите нужный CLI и войдите в него обычным способом. Ключ шлюза задаётся через окружение. Этот пример создаёт новый случайный ключ для текущей PowerShell-сессии и не выводит его:

```powershell
$keyBytes = New-Object byte[] 32
$rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
try { $rng.GetBytes($keyBytes) } finally { $rng.Dispose() }
$env:LLMGateway__Server__ApiKey = [Convert]::ToBase64String($keyBytes)
dotnet run --project src/LLMGateway.Api -c Release --no-build
```

API слушает `http://127.0.0.1:5157`; базовый путь для совместимого клиента — `http://127.0.0.1:5157/v1`. В том же клиенте настройте созданный ключ из переменной `LLMGateway__Server__ApiKey`. Не сохраняйте его в репозитории. Маршруты `/v1` требуют `Authorization: Bearer <key>` или `x-api-key`. `/health` проверяет только доступность HTTP-процесса.

**Ключ шлюза даёт доступ к управлению локальными аккаунтами и запуску настроенных программ.** Держите сервер на loopback и передавайте ключ только доверенным локальным клиентам. Для сетевого доступа нужны отдельные меры аутентификации, TLS и ограничения доступа.

Демонстрационный чат запускается отдельно:

```powershell
dotnet run --project src/LLMGateway.ChatApp -c Release --no-build
```

Встроенный HTTP-сервер чата создаёт собственный случайный ключ. Реальные запросы к провайдерам расходуют их обычные лимиты; автоматической ротации для обхода лимитов нет.

## Ограничения совместимости

- Поддерживаются текстовые `/v1/chat/completions`, `/v1/completions` и каталог моделей.
- Изображения, аудио, embeddings, `logprobs` и несколько вариантов ответа не поддерживаются.
- Tool calling эмулируется через промпт; шлюз сам не выполняет пользовательские функции.
- Некоторые sampling-параметры нативные CLI не применяют. Режим обработки настраивается.
- Лимит возвращаемого текста и резервная оценка токенов приблизительны; это не ограничение затрат провайдера.
- Запись модели в каталоге или `/health` не доказывает работоспособность аккаунта.
- WPF и разрешение Windows CLI-обёрток делают полное решение ориентированным на Windows.

Подробные контракты, ошибки, правила авторизации и пример встраивания — в [технической справке](docs/technical-details.md). Опциональная проверка реальных клиентов — [отдельная процедура](docs/REAL_PROVIDER_TESTS.md).

## Сборка для распространения

```powershell
dotnet publish src/LLMGateway.Api/LLMGateway.Api.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=false -p:PublishTrimmed=false -o artifacts/portable/Api
dotnet publish src/LLMGateway.ChatApp/LLMGateway.ChatApp.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=false -p:PublishTrimmed=false -o artifacts/portable/ChatApp
```

Запускайте EXE вместе с остальными файлами соответствующего каталога. .NET runtime включён, нативные LLM-клиенты устанавливаются отдельно. Профили и журналы по умолчанию находятся в `%LOCALAPPDATA%\LLMGateway`; они могут содержать личные пути и метаданные аккаунтов и не предназначены для публикации.

## Структура и лицензия

`Core` — контракты и маршрутизация; `Native` — CLI-адаптеры; `Server` — HTTP-поверхность; `Api` — отдельный хост; `ChatApp` — WPF-пример. Все проекты находятся в `src/`, тесты — в `tests/`.
