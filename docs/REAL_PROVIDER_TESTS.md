# Опциональная проверка реальных провайдеров

[← README](../README.md)

Публикационная проверка проекта ограничена офлайн-тестами. Исторические результаты на отдельных аккаунтах не доказывают совместимость сегодняшних CLI. Этот документ описывает ручную воспроизводимую проверку и не содержит списка личных профилей, тарифов или квот.

## Подготовка

1. Используйте отдельный тестовый аккаунт или профиль с небольшим допустимым расходом.
2. Установите выбранный нативный CLI из официального источника и выполните штатный вход. Зафиксируйте его версию.
3. Соберите проект и выполните офлайн-тесты из README.
4. Запустите локальный API с новым случайным ключом, как описано в README, либо ChatApp. Не открывайте порт наружу.
5. Выберите один конкретный аккаунт и модель. Проверка может запускать CLI и расходовать квоту; CI этого не делает.

## Проверки

| Проверка | Ожидаемый результат |
|---|---|
| Статус выбранного аккаунта | Готовность либо объяснимая ошибка входа/установки |
| Каталог моделей | Список или явно обозначенная недоступность; сам список не считается успешным модельным запросом |
| Короткий текстовый запрос | Непустой ответ выбранного клиента; используйте синтетический промпт без личных данных |
| SSE | Дельты, финальный результат и `[DONE]` при успехе; ошибка потока не должна маскироваться успехом |
| Отмена | Запрос прекращается и не оставляет принадлежащие ему процессы |
| Tool calling, если нужен | Валидная структура вызова объявленной функции; автоматического выполнения функции шлюзом нет |
| Квоты | Значения проверяются только у клиентов, которые их предоставляют; неизвестное значение не заменяется нулём |
| Отсутствующий клиент или неверная модель | Объяснимая ошибка без сырых секретов и внутреннего стека |

Не используйте продуктивные документы, чужие сессии или данные, которые нельзя отправлять выбранному провайдеру. Повторите нужные проверки после обновления CLI.

## Протокол результата

Сохраните локально дату, commit шлюза, версию Windows/.NET/CLI, название провайдера, проверенные сценарии и итог каждого. Если публикуете отчёт, удалите ключи, email, идентификаторы аккаунтов, локальные пути, содержимое сессий и персональные квоты. Не добавляйте файлы авторизации или сырые логи в репозиторий.

Провал live-проверки следует описывать отдельно от результата офлайн-тестов. Не объявляйте весь провайдер поддержанным по единственному ответу.
